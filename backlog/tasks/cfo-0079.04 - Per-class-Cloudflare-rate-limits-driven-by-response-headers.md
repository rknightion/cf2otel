## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The process-wide shared 0.5 rps limiter delays polling across independent REST and GraphQL quotas. Replace it with configurable per-class quotas while respecting upstream signals; no fairness, packing, interval or collector changes.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Replace the single process bucket with two, REST and GraphQL. Frozen keys: `cloudflare.rate_limit.rest.requests_per_second` default 3, `.rest.burst` default 5, `cloudflare.rate_limit.graphql.requests_per_second` default 0.8, `.graphql.burst` default 2; finite positive rate, burst in [1,1000], env via `CF2OTEL_CLOUDFLARE__RATE_LIMIT__REST__REQUESTS_PER_SECOND` and siblings. The legacy flat `requests_per_second`/`burst`, if explicitly set, applies to both classes and logs one deprecation warning naming the new keys; never a startup failure. REST: honour `retry-after` and pause the REST bucket for it so siblings do not stampede; parse `Ratelimit` (`r`, `t`) and, when `r` is at or below the REST burst, defer the next REST token until `t` seconds have passed; malformed headers are ignored. GraphQL: an `errors[].extensions.code == "budget"` response classifies as `rate_limited`, pauses only the GraphQL bucket for 300 s, and retries once after the pause if the context allows. Red then green through fake upstreams with short real durations, no injected production clock: (a) a saturated GraphQL bucket does not delay REST; (b) `Ratelimit: "default";r=0;t=1` delays the next REST request by at least 1 s; (c) a budget error pauses GraphQL only and classifies `rate_limited`. Each fails on R1's SHA. Existing tests pass; a test asserting the old 0.5 default or one shared budget changes only to the new contract, and the report names it. `docs/configuration.md` and `config.example.yaml` describe the new keys and the header behaviour. Security review and pre-land CodeRabbit accept; exact-SHA CI green
