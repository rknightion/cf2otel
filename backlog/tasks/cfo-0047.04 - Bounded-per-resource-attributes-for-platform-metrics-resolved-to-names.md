## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
D1, KV, Queues and Durable Objects metrics drop the database, namespace and queue identifiers on purpose to bound cardinality, which makes it impossible to see which resource is busy. R2 operations also lack the action type. Resource IDs should resolve to names via the read-only list endpoints and be capped.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 D1 database, KV namespace, Queue and DO namespace attributes are emitted as names, under a documented per-metric resource cap with a remainder bucket
- [ ] #2 R2 operation metrics carry the action type
- [ ] #3 Name lookups are cached and read-only
- [ ] #4 Every new signal and attribute is declared in internal/semconv, listed in docs/signals.md, and has a panel in grafana/build_dashboard.py
- [ ] #5 Any new token permission is added to the token permission matrix in the docs

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Loop16 E47D implements base metric resource names and R2 action type from verified GraphQL dimension descriptions and runtime list row shapes. Existing depth quantile selections remain unchanged. Domain-local one-hour successful/failed lookup caches use existing cfapi PageGetter, complete bounded pagination before publishing a map, and sticky per-metric admission of 49 normal label sets plus other remainder. Existing platform total cap remains. Preserve counter sums and max-gauge reduction. Request IDs never become metric attributes; root authorises updating affected metadata descriptions and tests that intentionally asserted old account-only selection, preserving ID-label prohibitions. Panels follow in DASH.
