## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Every comparable exporter is Prometheus-scraped, so many users have no OTLP metrics pipeline. Serving the same metrics on an opt-in /metrics endpoint lowers the adoption bar without changing the OTLP path.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Admit after core-chain terminal/publication parks. Use aligned experimental OpenTelemetry Prometheus exporter v0.68.0 from official v1.46.0 release manifest and module metadata (Go minimum 1.25, SDK dependencies 1.46), alongside the existing periodic OTLP reader on one MeterProvider. New internal/promexport package owns private registry, handler and listener lifecycle. Opt-in prometheus.enabled false; listen localhost:9465 by default, separate from health. Explicit all-interface example binds use :9465 with an unauthenticated-metrics exposure warning. One optional PrometheusReader provider option; no new collector execution/emitter or public signal. Explicit underscore/suffix translation, no resource constant labels/target-info/scope-info. Scheduled normal mode only; dry-run, once and print-effective-config do not open a listener. Root owns outward enablement, dependency-version review, exact-SHA review/landing/CI.
<!-- SECTION:PLAN:END -->
