## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When something breaks, the first question is whether it is Cloudflare. The public status page API gives component and region status without credentials; an opt-in collector turns it into a gauge and incident log events.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Loop15 E50D: doc- and live-verified public status API, opt-in statuspage.status collector using its own bounded HTTP client and no credentials. Summary supplies components; all-incidents endpoint retains resolved updates absent from summary. Bounded component gauge snapshots, incident-update log events filtered by scheduler windows; no full-history/backfill guarantee beyond the vendor latest-50 endpoint. New names/config freeze recorded privately by root. Source slice owns package and append-only registries; dashboard panel follows in the dedicated DASH chain before AC3 closes.

Root amendment after independent local seam mapping: supersede the unimplemented statuspage.status registration with independently opt-in statuspage.components (SnapshotCollector) and statuspage.incidents (WindowCollector), both default off with five-minute intervals. Components publish a complete validated current-state summary through the existing expiring snapshot emitter; incident logs remain buffered and checkpointed after successful commit. No all-channel atomicity is promised or required by AC1/2. No shared buffer/scheduler/emitter changes. Earlier string truncation attribute remains explicit. Root vendor documentation and all captured component/update field types were reverified; dashboard remains a later dedicated slice.
